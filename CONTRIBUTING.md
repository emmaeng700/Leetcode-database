# Contributing to LeetCode Database

Thank you for your interest in contributing to the LeetCode Database! This document provides guidelines for contributing to this project.

## 🤝 How to Contribute

### 1. Reporting Issues
- Check existing issues before creating a new one
- Use clear, descriptive titles
- Include relevant details about the problem
- Provide examples when applicable

### 2. Adding New Problems
When adding new LeetCode problems:

#### Format Requirements:
- **Problem Title**: Clear and descriptive
- **Problem Statement**: Complete description with examples
- **Constraints**: All relevant constraints listed
- **Solution**: Well-commented, optimized Python code
- **Complexity Analysis**: Time and space complexity

#### Example Format:
```
## Problem X: [Problem Title]

[Problem description with examples]

Constraints:
- [List all constraints]

Solution:
class Solution:
    def methodName(self, params) -> returnType:
        # Your optimized solution with comments
        pass

Time Complexity: O(...)
Space Complexity: O(...)
```

### 3. Code Quality Standards
- **Clean Code**: Write readable, well-structured solutions
- **Comments**: Add comments for complex logic
- **Optimization**: Provide efficient algorithms when possible
- **Testing**: Ensure solutions work with provided examples

### 4. Pull Request Process
1. Fork the repository
2. Create a feature branch (`git checkout -b feature/add-new-problems`)
3. Add your problems following the format guidelines
4. Test your solutions with the provided examples
5. Commit your changes with clear messages
6. Push to your fork and submit a pull request

### 5. Categories We Accept
- **Easy Problems**: Fundamental concepts, basic algorithms
- **Medium Problems**: Intermediate techniques, common patterns
- **Hard Problems**: Advanced algorithms, complex optimizations

### 6. Review Process
- All submissions will be reviewed for:
  - Correctness of solutions
  - Code quality and readability
  - Proper formatting
  - Appropriate difficulty classification

## 📝 Style Guidelines

### Code Style
- Use clear variable names
- Follow Python PEP 8 conventions
- Include docstrings for complex functions
- Maintain consistent indentation

### Documentation Style
- Use proper markdown formatting
- Include clear problem descriptions
- Provide multiple examples when helpful
- Explain algorithmic approaches

## 🚀 Getting Started

1. Browse existing problems to understand the format
2. Choose a problem category (Easy/Medium/Hard)
3. Follow the contribution format
4. Submit your pull request

## 🎯 Priority Areas

We especially welcome contributions in:
- Dynamic Programming problems
- Graph algorithms
- Tree and binary search problems
- System design related problems
- Optimization of existing solutions

## ❓ Questions?

If you have questions about contributing:
- Open an issue with the `question` label
- Check existing discussions
- Review the README for project overview
